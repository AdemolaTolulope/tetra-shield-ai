# NAMING ANALYSIS

Constraint from directive: name must be memorable, meaningful, pronounceable, honest,
platform-capable; not chosen for acronym glamour alone.

## Candidates evaluated
| Name | Reads as | Verdict |
|---|---|---|
| TETRA-SHIELD (module) | "Tetracycline Environmental Transformation, Resistance & Safety Hazard Intelligence Engine" | **KEEP for module 1** — expansion is literal and accurate; tied to tetracycline class, not reusable for mycotoxins |
| BioShield-X (platform) | "BIOlogical transformation Hazard Intelligence, Evaluation & Decision for contaminant X (X = variable)" | **ADOPT for platform** — X explicitly encodes the plug-in contaminant modules; pronounceable; no overclaim (it shields by *intelligence*, not by magic) |
| DetoxRank | — | rejected: "detox" is exactly the overclaim the product exists to police |
| EnviroZyme AI | — | rejected: hype suffix, vague |
| RemediGraph | — | rejected: implies graph-ML that we deliberately do not use |

## Decision
- Platform: **BioShield-X** — "an environmental BioAI decision engine".
- Module 1 (this prototype): **TETRA-SHIELD** — tetracycline / water / microbial-enzymatic /
  cassava-circular configuration. Subsequent modules (e.g., ciprofloxacin, mycotoxins)
  inherit the platform with their own SHIELD names only when their evidence layers are real.
- Rationale documented to satisfy "do not permanently lock the name": the *platform* name
  is the permanent asset; module names are evidence-scoped.
